Calculator Bug Fixed — Boxed Result Still Not Reproduced

The interactive calculator above previously had a dead-code bug: its threshold loop set \(m_n = n \cdot M_{\rm KK}\) and only accumulated a contribution when \(m_n < M_{\rm KK}\) — a condition that is never true for \(n \geq 1\), so the KK threshold corrections \(\Delta_i\) were silently always zero, regardless of \(N_{\rm max}\) or \(M_{\rm KK}\). That guard has been removed so the calculator now implements the formula in Eq. [above] as written. However, running it with this page's own default slider values (\(\log_{10}(M_{\rm KK}/{\rm GeV}) = 16.3\), \(\alpha_{\rm GUT} = 0.0385\), \(N_{\rm max} = 20\)) does not reproduce the boxed αs(MZ) = 0.1180, sin²θW = 0.2312 result — the corrected sum is large enough to push the predictions well away from the observed values. This is flagged rather than silently tuned to match; the boxed "Optimal Threshold Solution" above should be treated as unverified until someone establishes what parameter choice (if any) actually reproduces it with the corrected code.
